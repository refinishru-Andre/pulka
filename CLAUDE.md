# Пулька («Людочка»)

Веб-приложение для записи и расчёта очной игры в преферанс (Питер / ленинградка,
домашние конвенции Андрея). Правила и формулы — в [SPEC.md](./SPEC.md).

- **Live:** https://refinishru-andre.github.io/pulka/ (GitHub Pages, ветка `gh-pages`)
- **Стек:** Vite + React + TS + Tailwind + Zustand + PWA
- **Облако:** self-hosted Supabase на Яндекс-сервере `178.154.204.13`,
  API `https://pulka-api-178-154-204-13.sslip.io`, схема БД `pulka`

## Команды

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # 46 тестов движка
npm run typecheck
npm run build      # сборка в dist/
npm run deploy     # dist/ → ветка gh-pages (сначала build!)
```

Пересчёт всех облачных партий по актуальной логике движка:
`SERVICE_KEY=xxx npx tsx scripts/recalc-cloud.ts [gameId]`

## Структура

- `src/engine/` — чистая логика: `calc.ts` (расчёт сдачи), `raspas.ts` (эскалация
  распасов), `settle.ts` (кто кому должен), `stats.ts` (статистика), `rules.ts`
- `src/store/game.ts` — Zustand + persist в LocalStorage (`pulka-game-v1`)
- `src/store/orphans.ts` — партии, не попавшие в облако (`pulka-orphans-v1`)
- `src/store/sync-status.ts` — состояние записи в облако для индикатора на столе
- `src/supabase/` — `client.ts`, `auth.ts` (вход по кодовому слову),
  `sync.ts` (партии), `people.ts` (справочник игроков)
- `src/screens/` — `Login`, `GamesList`, `NewGame`, `Table`, `DealForm`, `Stats`
- `supabase/*.sql` — схема и RLS-политики (применяются на сервере вручную)

## Ключевые решения и грабли

- **`deals[]` — единственный источник истины.** `pool/mount/whists` это кеш:
  при каждой загрузке (`loadGame`, `fetchGames`, `onRehydrateStorage`) состояние
  пересчитывается из истории сдач. Меняешь формулы — старые партии подтянутся сами.
- **`recalculate()` НЕ пушит в облако** — иначе локальные данные затирают свежие
  облачные (см. коммит efd82e5).
- **Локально хранится только ОДНА текущая партия.** Перед её заменой партия
  откладывается в `orphans` — иначе несинхронизированная партия пропадала совсем.
- **Синхронизация сверяется по ЧИСЛУ СДАЧ, не по id** (`isMissingFromCloud`).
  Облачная копия бывает обрезанной: связь оборвалась посреди партии. Побеждает
  версия с бо́льшим числом сдач — `loadGame` не даёт облаку затереть локальную.
- **`uploadGame` возвращает результат** (`ok`/`guest`/`failed`), а не `void`.
  Отправка повторяется каждые 20 с и по событию `online`. Никогда не удаляй
  партию из запаса, не убедившись в `'ok'`.
- **`scheduleSync` нельзя звать на завершённой партии** — RLS запрещает UPDATE
  при `finished = true`, будет вечный повтор и ложная тревога. Проверяй
  `isGameFinished` (см. SOLUTIONS.md).
- **Вход = кодовое слово → детерминированный аккаунт** (email/пароль = хэш слова).
  Вход и создание коллекции — РАЗНЫЕ действия: опечатка не должна молча создавать
  новый пустой аккаунт (см. SOLUTIONS.md).
- **Масть не записывается.** На расчёт влияет только уровень 6–10. Единственное исключение —
  6♠ (Сталинград): в `Contract.suit` пишется `S` только для него, у остальных игр поля нет.
- **Статистика склеивает игроков по ИМЕНИ** (строка в `game.players`), не по id.
  Имя нормализуется в `people.ts`: trim + первая буква заглавная.
- **Завершённые партии защищены на уровне БД** (`rls_finished_protection.sql`):
  UPDATE разрешён только пока `finished = false`.
- **Домен `*.sslip.io` бывает недоступен** у мобильных провайдеров — это главная
  причина «не пускает в приложение». На экране входа есть кнопка проверки связи.
